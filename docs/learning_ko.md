# 내가 설명할 수 있어야 할 내용

## 1. 어떤 데이터인가?

미국 CFPB가 공개했던 소비자 불만 본문이다. 현재 API에서 글을 받을 수 없어 공식 과거 보관 자료를 사용했다. 2024년 1~6월의 신용카드, 예금계좌, 주택담보대출, 채권추심 네 상품에서 작은 표본을 뽑았다. 본문이 없는 글, 너무 짧거나 긴 글, 영어 검사에 걸린 글, 중복과 매우 비슷한 글을 제외했다. 최종 3,192건이다. 실제 고객 전체를 대표하지 않는다.

## 2. 모델은 무엇을 배웠나?

글에 등장하는 단어·두 단어 조합을 숫자로 바꾸고(TF-IDF), 어떤 표현이 어떤 상품 라벨과 함께 자주 나타나는지 배웠다(Logistic Regression). 예를 들어 mortgage payment 같은 표현이 도움이 될 수 있지만 단순 단어 사전은 아니다. 여러 표현에 배운 가중치를 합쳐 유형을 고른다. 사람이 읽듯 상황이나 피해 정도를 이해했다고 주장할 수 없다.

학습은 1~3월 1,681건, 검토 기준 선택은 4월 489건, 마지막 평가는 5~6월 1,022건이다. 날짜·정답·회사 답변은 입력이 아니다. 모델 점수는 정답일 확률로 검증하지 않았다.

## 3. 에이전트는 무엇을 하나?

실제 LLM이 두 도구를 부르고 결과를 읽게 하는 코드가 있다. 분류 도구는 유형·점수·입력 검사 결과를, 정책 도구는 검토 기준·예시 팀을 준다. LLM은 순서를 선택하고, 두 결과에 근거해 JSON으로 제안 또는 검토 필요를 설명한다. 다른 유형이나 팀을 만들거나 필수 검토를 무시하면 프로그램이 거부하고 사람 검토로 바꾼다.

**현재 실제 API 실행은 0건이다.** 따라서 “에이전트를 구현했고 소프트웨어 흐름을 테스트했지만, 실제 에이전트 평가는 아직 하지 않았다”가 정확하다. 테스트의 가짜 API 응답은 프로그램을 확인하는 도구이며 연구 결과가 아니다.

## 4. 에이전트 없이 할 수 있는 것은?

분류 모델 실행과 검토 기준 적용은 Python만으로 가능하다. 지금 공개한 수치는 이 방식의 결과다. LLM이 설명을 붙이는 것이 비용과 오류 가능성을 감수할 만큼 도움이 되는지는 아직 모른다. 에이전트를 붙였으니 더 좋다고 말하지 않는다.

## 5. 사람 검토 기준은?

비어 있거나 길이·영어 검사에 맞지 않는 입력은 검토로 남긴다. 정상 입력은 1등 유형 점수와 2등 유형 점수 차이가 0.1 미만이면 검토로 남긴다. 여러 후보 중 개발 데이터에서 정한 기준이고 마지막 평가에서는 바꾸지 않았다. 선택된 절대 점수 기준은 0이어서 사실상 작동하지 않는다. 실제 업무에 적절한 기준인지는 별도 판단이 필요하다.

예: 1등 0.48, 2등 0.43이면 차이가 0.05이므로 검토한다. 이것은 정답 확률 48%라는 뜻이 아니다.

## 6. 비교 결과는?

평가 1,022건을 전부 분류하면 공개 라벨과 다른 것이 140건(13.7%)이었다. 규칙을 쓰면 145건(14.2%)을 검토로 남기고 877건을 제안했다. 제안한 것 중 63건(7.2%)이 라벨과 달랐다. 원래 오류 140건 중 77건을 검토로 남긴 것이다. 나머지 검토 68건은 원래 예측이 라벨과 맞았다. 검토량이라는 대가가 있다.

LLM 평가용으로 고정한 별도 100건에서는 모두 분류하면 오류 10건, 규칙을 쓰면 제안 83건 중 오류 4건과 검토 17건이다. 나중에 LLM과 비교할 때는 이 100건 기준을 써야 한다.

## 7. 입증하지 못한 것은?

사람이 실제로 고쳤는지, 직원 시간이 줄었는지, 비용이 절감됐는지, 고객 만족이 나아졌는지는 측정하지 않았다. 공개 상품 라벨도 완벽한 업무 정답이 아니다. 언어 검사·중복 제거·범위 밖 입력 판별도 완벽하지 않다. 실제 LLM의 정확도·비용·속도·지시문 공격 대응은 평가 대기다.

## 코드 읽는 순서

1. `protocol.json`: 학습 전 고정한 선택.
2. `cra/data.py`: 필요한 자료 수집, 작은 표본, 중복 처리, 날짜별 분할.
3. `cra/model.py`: 단어를 배워 분류하고 개발 데이터로 검토 기준 선택.
4. `cra/evaluate.py`: 분류 범위와 오류를 함께 계산.
5. `cra/agent.py`: 실제 API 도구 호출, 출력 확인, 실패·캐시 기록.
6. `cra/cli.py`: 위 과정을 순서대로 실행.
7. `app/streamlit_app.py`: 방문자에게 핵심을 보여주는 화면.

## 내가 직접 확인하고 말할 부분

구현과 초기 문서는 AI 지원을 받았다. 모든 코드를 혼자 썼다고 설명하지 않는다. 질문·범위·해석을 나 자신이 이해하고 판단했는지는 아래를 직접 해본 뒤 확인한다.

- 준비된 카드 예시와 일부러 애매한 예시를 실행하고 결과를 비교한다.
- 왜 사람에게 남겼는지 도구 점수와 기준을 보고 설명한다.
- “오류가 7.1%니까 92.9%는 안전하다”가 왜 과장인지 설명한다.
- 검토량과 오류 중 어떤 것을 더 중요하게 볼지, 그 이유를 내 말로 쓴다.

아직 완료하지 않은 활동을 원서에서 완료했다고 쓰지 않는다. README와 보고서의 reflection은 이 확인을 거쳐 본인 표현으로 다듬을 초안이다.
